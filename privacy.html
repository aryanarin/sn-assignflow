SN Assignflow — Privacy Policy

Version 4.0.0

There is no server behind this extension. Nothing you configure, and nothing it reads from ServiceNow, is ever transmitted to the author or to any third party. All data stays in your browser's local extension storage, and the only host it ever contacts is the ServiceNow instance in the tab you are already using.

What is stored, and where

Everything is held in chrome.storage.local — local to your browser profile on your machine. None of it is synced by the extension.

DataWhy it exists
Assignment groups: name, table, filter query, agent list The configuration that tells the engine what to assign and to whom.
Global user list: display names, ServiceNow user IDs, sys_ids, optional email addresses So agents can be declared once and reused, and so a user ID need only be resolved to a sys_id once.
Round-robin position per group So the rotation continues where it left off rather than restarting each run.
Rules, keep-alive settings, theme Your preferences.
Assignment counters and a capped log of recent activity (500 entries) The statistics in the widget and the Logs section. Log history can be turned off in Settings.
Widget position and open state So the widget stays where you put it across ServiceNow navigations.

The user IDs, names, email addresses and sys_ids in the global list are personal data about your colleagues. They are entered by you or fetched from your own instance, they never leave your browser, and Settings → Delete all SN Assignflow data removes them immediately and permanently.

Network requests

Three, all to the ServiceNow instance in the tab you are on, all relative to its own origin:

  • Reading tickets. A GET to the Table API using your group's filter query, requesting only sys_id and number.
  • Writing an assignment. A PATCH to the Table API setting assigned_to on a single record. Nothing else on the record is read or changed. With Dry run enabled this request is never made.
  • Resolving a user ID. A GET to sys_user requesting sys_id, name, user_name and email for the agents you configured. Happens once per agent and is then cached.

Plus the keep-alive ping: a GET to a small endpoint on the same instance (/api/now/session, /now/nav/header or /stats.do) on a timer you control. It sends only the session cookie your browser already sends, reads nothing from the page, and keeps nothing from the response. It can be switched off in Settings, though it is forced on while the engine is running so an unattended run isn't ended by a logout.

Every one of these rides the ServiceNow session already open in that tab. The extension never handles your password, never obtains a token of its own, and never sends credentials anywhere other than the instance they belong to.

Reading the page

The extension reads exactly one value out of the ServiceNow page: the user token (g_ck), which the Table API requires in order to accept a write. It is read from the page's own JavaScript context, kept in memory for the lifetime of the tab, and never stored or transmitted.

No form fields, ticket contents, attachments, keystrokes or browsing history are read, and no page content is collected.

Permissions, and why each is needed

PermissionReason
storageTo save your groups, user list and settings locally.
tabsTo find the active ServiceNow tab when you launch the widget, and to open the configuration page.
scriptingTo read the user token from the page's own context, and to inject the widget into a tab that was already open when the extension was installed.
Host access to *.service-now.com ServiceNow's own cloud domain. The only host requested when you install the extension.
<all_urls> — optional, off by default Never requested at install time and never requested on its own. Many instances are hosted on-premise or on a company domain that cannot be known in advance, so Settings → Instances lets you either name those hosts individually or, if you prefer, allow all sites in one step. Your browser asks before either is granted, and you can withdraw it at any time.

No customer or employer domain is built into this extension. Apart from ServiceNow's cloud domain, every host it can reach is one you added yourself.

Allowing all sites is a convenience, not a statement that every site is ServiceNow. Even with it granted, the widget and the keep-alive ping only act on a page once it has been confirmed to be a ServiceNow instance — either because you named its domain or because the page carries ServiceNow's own markers. On any other site the extension does nothing and sends no requests.

There is no remote code: every line the extension runs ships inside the package.

Files you export

Exported groups, user lists and backups are written to your own downloads folder and go nowhere else. They do contain real names, user IDs and sys_ids, so treat them as you would any staff list — in particular, think twice before committing one to a shared repository.

Data collection

None. No analytics, no telemetry, no crash reporting, no advertising identifiers, no cookies set by the extension. The Firefox listing declares no data collection, and that is accurate.

Children

This is a workplace tool for ServiceNow administrators and is not directed at children.

Changes to this policy

Any change is published with a new version of the extension and recorded in the changelog. If a future version were ever to collect or transmit data, that would require a new permission and your explicit consent.

Questions about this policy, or about how the extension behaves, are welcome via the project's repository.
