Instances
ServiceNow's own cloud domain is supported out of the box. If your instance is hosted somewhere else — on-premise, a vanity domain, behind a proxy — add it here. Your browser will ask before granting access to that host, and nothing is granted until you approve it.
Enable on all websites
The simplest option: works on any instance with no further setup. Prefer naming your domains below if your organisation restricts what extensions may access. Either way the widget only ever acts on pages that are actually ServiceNow.

Session keep-alive
Pings a small endpoint on the instance in each open ServiceNow tab so the session doesn't time out. It sends only the cookie your browser already sends, reads nothing from the page, and keeps nothing from the response.

Engine location
Runs inside the ServiceNow tab, not in the background, so its timer survives and every request is same-origin to your instance.
Assignment order
Round robin over the active agents of a group, in the order you list them. The position is remembered per group between runs.
Agent identity
A ServiceNow user ID or a sys_id. User IDs are resolved once and cached.
Network activity
The Table API on your own instance, plus the keep-alive ping. Nothing is sent anywhere else — there is no server behind this extension.

Getting started
1. Add the people you dispatch to under Agents, then use Resolve sys_ids with a ServiceNow tab open.
2. Create a group, paste a filtered ServiceNow list URL into the converter, and add agents to the rotation.
3. Turn on Dry run under Rules and start the widget once to confirm the filter selects what you expect.
4. Turn dry run off and let it run.
